PUBLISHING A LEDGDEX ONLINE


You publish a ledgdex in the same way as any dex, with dexweb. The destination is a git repository or a folder. GitHub Pages hosts git repositories at no cost.

One thing is different: config.json has "append_only": ["ledgdex.jsonl"]. So dexweb refuses to publish a ledger that does not extend the published ledger.

1. Make a repository. On GitHub, use YOU.github.io, or any repository with Pages on.

2. Name the repository when you run init, or at a later time in "publish" in config.json: 

ledgdex init shop --name "Mango Farm" --key farm --url https://YOU.github.io \
    --dest git@github.com:YOU/YOU.github.io.git --branch main

3. Publish after each change: 

ledgdex publish shop

4. Others read your ledgdex at its address: 

ledgdex verify https://YOU.github.io

You can publish from many devices. Each device keeps a copy of the dex and has its own device key.

If a different device published first, ledgdex publish signs the unpublished entries of this device again, after the published ledger. Then it publishes again.

So there is one history, and never two entries at one position. Example: Publish runs these steps with a local repository.

Static hosting is enough. Examples are GitHub Pages, any web server, or a shared folder on a local network. Computers can trade over plain HTTP (Bots and Agents).
