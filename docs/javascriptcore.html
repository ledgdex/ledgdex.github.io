JAVASCRIPT CORE


The JavaScript core is ledgdex in plain JavaScript: the same rules as the Python package, in ES modules in js/ with no dependencies, no npm and no build step. It makes the same bytes, ids, signatures, states and pages as Python: both are checked against shared test vectors and against each other with differential fuzzing on every push. The viewer is built on it.

Where it runs: any current web browser, and Node 20 or later (the tests use Node 22). Other JavaScript runtimes are not tested.

What is in it:

core.js      keys, messages, entries, Ledger (verify a ledger, add entries), newLedger
state.js     state(ledger): offers, claims, auctions, disputes, admissions, ...
canon.js     canonical JSON and hashes: canon, canonString, hash, parse
render.js    the pages a ledgdex shows, and helpers such as amount and esc
sig.js       signer(secret): Web Crypto Ed25519 when there is one, else the built-in code
keystore.js  sealKey and openKey: a key sealed with a passphrase
ed25519.js   sha.js   dexweb.js   zip.js   the parts underneath

Every function, with its arguments, is in the API Reference.

Load it in a web page from the ledgdex site, as a module:

<script type='module'>
  import { Ledger } from 'https://ledgdex.github.io/core.js';
  import { state } from 'https://ledgdex.github.io/state.js';
</script>

That always gives the latest published core. For a site of your own, copy js/ from a release (for example the v1.0.17 tag) onto your site and load it from there: a script loaded from another site can change without you knowing, and it runs with your page's rights. In Node, import the files from a copy of js/, as the examples below do.

What it is good for:

1. Checking ledgers in the reader's own browser, so nobody has to trust your server. Example: Shop Web Page shows a shop's offers on its own website, read from its ledger.

2. Buying with nothing to install: a buyer keeps a key sealed in the browser, signs orders and keeps a ledger of its own, as the viewer does. Example: Sign in the Browser.

3. Programs and bots written in JavaScript: read, check and follow ledgers from Node. Example: Verify in Node.

4. Making ledgers and messages in code, the same way the Python library does. Example: JavaScript.

When to use Python instead: for the command line and everything it does over time. Publishing a dex with dexweb, ledgdex check with its kept copies and receipts, collecting messages from many dexes with record --from, keys kept on disk, and the daily check workflow are in Python only. The JavaScript core has no command line and does not publish.

Reading ledgers from other sites: a page can always read files from its own site. To read another site's ledgdex.jsonl, that site must allow it (CORS). GitHub Pages does, for every site it serves. If a host does not, download the file and open it, as the viewer lets you.

Keys in a browser: never store a secret key as it is. sealKey(secret, passphrase, publicKey) returns a sealed box you can store (PBKDF2-SHA-256 with 600,000 rounds, then AES-256-GCM; the passphrase has at least 12 characters), and openKey(box, passphrase) opens it. Every page on one site can read what that site stores, so keep keys on a site that serves nothing else you do not control. signer(secret) signs with the browser's own constant-time Ed25519 (Web Crypto) when it has one; verifying always uses the built-in code, so every browser judges a ledger the same way.

Things to keep in mind: everything in a ledger is data from someone else. Put its text on a page with textContent, or through esc from render.js, never as raw HTML; and check whole before you trust anything in a ledger.
