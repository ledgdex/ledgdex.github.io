SELL YOUR CATALOG ON LEDGDEX


A shop is a ledgdex with one offer for each product. ledgdex shop makes the complete shop from one JSON file, the catalog. You do not write offer files. A bot or a person gives the catalog and a GitHub repository. Then ledgdex makes the shop and publishes it with dexweb.

ledgdex shop catalog.json --repo OWNER/NAME

In Python, for bots: 

from ledgdex.shop import shop
result = shop('catalog.json', repo='OWNER/NAME')

The result tells the dex folder, the ledger id, the address of the shop, and how many offers ledgdex kept, signed and withdrew.

A catalog: 

{"shop": {"name": "Penguin Shop", "currency": "USD",
          "pay": [{"method": "card", "to": "https://pay.example/penguin"}],
          "about": "Gear for cold places", "terms": "Delivery in 5 days.",
          "repo": "OWNER/NAME"},
 "products": [{"title": "Ice axe", "price": 4999, "quantity": 20, "text": "Steel, 70 cm"},
              {"title": "Snow boots", "price": 12900, "quantity": 15, "unit": "pair"}]}

These fields are necessary:

- shop.name: the name of the shop.

- shop.currency: one currency for all products, for example USD.

- shop.pay: one or more payment methods. Each method has method and to.

- For each product: title, price and quantity. Each title must be different. The price is an integer in the smallest unit of the currency. For example, USD 49.99 is 4999.

These fields are optional:

- In shop: about, terms, unit, allow, arbiter, url, root and key.

- Where to publish, in shop: one of repo (a GitHub repository, OWNER/NAME), dest (a git address) or folder (a folder). With repo or dest, also branch (the default is main) and site_path.

- For each product: text, media, unit, terms, allow and expires. A product without unit, terms or allow uses the value of the shop.

- products itself. A shop can start with no products.

Ledgdex refuses a field that is not in these lists. Thus a field with a spelling error cannot go missing. Ledgdex examines all products before it signs. If one product is wrong, ledgdex signs nothing, and the error names the product.

Run ledgdex shop again after you change the catalog. Ledgdex makes the shop the same as the catalog:

- A product that did not change keeps its offer. Ledgdex signs nothing for it.

- A new product gets a new offer.

- A changed product, for example with a new price, gets a new offer. Ledgdex withdraws the old offer, because a signed offer cannot change.

- Ledgdex withdraws the offer of a product that is not in the catalog now.

- A product that is sold out keeps its offer. Ledgdex does not offer it again. To add stock, change its quantity.

The same catalog again signs nothing. Thus a bot can run ledgdex shop each day with its current catalog.

Options: --dex sets the dex folder. The default is the shop name in lowercase, with - between the words. --repo replaces the repo, dest, folder and url of the catalog. --no-publish makes or changes the shop, but does not publish it.

GitHub Pages: ledgdex pushes the site to the repository, but it cannot turn on GitHub Pages. For a new repository, turn on Pages one time (Settings, Pages, branch main). The repository OWNER.github.io has Pages already. The shop is at https://OWNER.github.io/NAME. With site_path, it is in that folder.
